# docfig — 문서를 한눈에 읽히게 하는 도식 설계

글로 길게 조립해야만 머릿속에 그려지는 **인과·흐름·대립·상관관계·계층 구조**를 외부 의존성 없는 인라인 SVG 도식으로 설계해 HTML 문서에 넣는다. 외부 라이브러리·웹폰트·이미지를 쓰지 않아 오프라인·폐쇄망 환경에서도 그대로 열린다. 보조 도구는 [scripts/figlib.py](./scripts/figlib.py), 세부 패턴 예시는 [references/patterns.md](./references/patterns.md). 사용자의 언어로 대화한다.

## 입력과 시작하기

- 요청에서 **대상 문서(또는 원문 자료) 경로**와 **독자에게 전달할 핵심 구조·인사이트**를 먼저 파악한다.
- 원문·코드·설정·데이터에서 직접 확인 가능한 사실과 상관관계는 먼저 분석하고 사용자에게 되묻지 않는다.
- **특정 문서 양식을 다른 주제에 억지로 복제하지 않는다.** 기술 아키텍처, 데이터 파이프라인, 개념·철학 분석, 운영 절차 등 **대상 자료의 고유 어휘와 호흡**에 맞춰 문서 구조와 도식 종류를 고른다.

## 1. 그릴지 말지

- 그림은 **여러 요소의 관계·분기·상관성을 한눈에 보여 줄 때**만 넣는다. 한 문장이면 끝나는 사실은 글로 둔다.
- **명사 나열이 아니라 작동 원리(메커니즘)를 그린다.** 상자 이름만 늘어놓지 말고, 무엇이 어떤 조건·계기를 통해 무엇을 낳거나 깨뜨리는지 화살표 동사로 적는다.
- **실재·확정과 가설·위험·미구현을 모양으로 가른다.** 작동 중인 경로·확립된 원리는 실선으로, 아직 없는 연결·오류 함정·가설은 점선(`gap`, `dashed=True`)으로 구분한다.
- 그림이 글과 표를 대체하지 않는다. 그림은 **구조적 통찰**을 맡고, 정확한 정의·수치·원문 근거는 표와 본문이 맡도록 역할을 나눈다.

## 2. 관계 모양(위상)에 따라 어떤 도식을 쓸지

모든 관계를 무조건 '상자와 선' 하나로 그리면 거미줄이 된다. 분석한 관계의 모양에 맞춰 도식을 고른다(상세 코드는 [references/patterns.md](./references/patterns.md) 참조).

| 보여 줄 관계의 모양 | 적합한 도식 | `figlib` 도구 |
| --- | --- | --- |
| 순차 처리, 조건 분기, 선순환 vs 악순환 회로 (상자 ~12개 이내) | 흐름·회로도 (정적 SVG) | `Flow` + `lane`·`card`(`box`)·`arrow`·`note` |
| 기존 통념 ↔ 재정의, 변경 전(AS-IS) ↔ 변경 후(TO-BE) 1:1 전환 | 전환 대조도 (정적 SVG) | `compare` |
| 두 축 사이의 다대다 상관관계·관여도·역할 비교 | 매핑·상관 격자 (정적 SVG) | `matrix` |
| 3~6단계에 걸친 12~40개 노드의 다중 인과·파급 사슬 | 초점 관계망 (선택 강조형) | `network` |

## 3. 읽기 쉬운 도식의 6원칙

1. **거시 먼저, 세부는 점진적으로 (정보 밀도 제어)**:
   - 처음부터 수십 개 상자와 수백 개 세부 속성을 한 화면에 다 펼쳐 놓지 않는다.
   - 문서 첫머리에 **5~8개 핵심 묶음 이내의 거시 도식**으로 전체 작동 원리를 10초 안에 이해시키고, 세부 항목은 절별 소형 도식·요약 표·접기(`<details>`)·선택 강조로 단계화한다. 상자 하나에는 **제목 + 핵심 요지 1~2줄**만 담는다.
2. **배치 축 = 논리 축, 단방향 질서 (역방향 간선 0개)**:
   - 대상을 일련번호나 나열 순서대로 여러 줄에 쪼개 놓지 않는다. **원인 → 매개 → 귀결**, **입력 → 변환 → 출력**, **문제 → 해체 → 해법**처럼 위치 자체가 의미를 갖도록 3~6개 이내의 단계 축을 세우고 머리말(`lane` / `stages`)에 기준을 적는다.
   - 양방향·순환처럼 보이는 관계도 선행 조건과 후행 결과로 분해해 **왼쪽 → 오른쪽**(같은 열에서는 위 → 아래) 한 방향으로 편다. 양끝 동그라미 대신 분명한 삼각형 화살촉을 쓴다.
3. **연결 대상을 같은 높이에 정렬**:
   - 둘째 열부터 무작정 맨 위(`y=0`)에서 쌓지 않고, 연결된 왼쪽 선행 상자들의 높이 근처에 맞춰 대각선·계단식 장거리 교차선을 줄인다(`network`는 자동 정렬).
4. **바탕은 조용하게, 강조는 얇은 색 막대로 절제**:
   - 상자·항목마다 원색 배경과 배지를 다닥다닥 붙이지 않는다. 바탕은 중립 표면(`--fg-panel`)으로 통일하고, 범주 차이는 **왼쪽 4px 색 막대(최대 4색)**와 **실선/점선 테두리**로만 차분하게 구분한다.
   - 색은 `figlib` 전용 변수(`--fg-*`, 밝은·어두운 화면 자동 대응)만 쓴다.
5. **선이 많아질 때는 골격과 초점을 분리 (`network`)**:
   - 노드가 많아 선이 겹칠 때는 평상시에 연한 골격선(`opacity 0.36`)만 깔아 시야를 어지럽히지 않고, 독자가 특정 노드를 골랐을 때만 **선행 요인(초록)**과 **후행 파급(파랑)**을 끝까지 추적해 보여 준다.
6. **캡션에 '이름'이 아니라 '통찰'을 적는다**:
   - `<figcaption>`에는 "○○ 구조도" 같은 제목 반복 대신, **이 도식에서 읽어야 할 핵심 상관관계·결론 한두 문장**을 적는다. 비밀정보·토큰·비공개 주소·민감 개인정보는 절대 그리지 않는다.

## 4. 모양과 색 부호

| 의미 | `Flow.card` / `network` (`tone`) | `Flow.box` (`kind`) | `matrix` 칸 |
| --- | --- | --- | --- |
| 기점·원천·기본 대상 | `'neutral'` (회색 막대) | `'item'` | `'rel'` / `'r'` (연관·읽음) |
| 핵심 메커니즘·처리·강한 상관 | `'accent'` (파랑 막대) | `'step'` / `'llm'` | `'strong'` / `'w'` (핵심·씀) |
| 전환점·주의·사람 개입 | `'warn'` (주황 막대) | `'person'` / `'pii'` | `'warn'` / `'h'` (긴장·수동) |
| 해법·도달점·성립 | `'ok'` (초록 막대) | `'ok'` | `'pos'` / `'ok'` (해법·완료) |
| 함정·단절·가설·미구현 | `'gap'` 또는 `dashed=True` (점선) | `'gap'` | `'gap'` / `'f'` (점선), `'empty'` |

## 5. 실행 순서

1. **내용과 상관관계를 먼저 분해한다.** 원문·코드를 끝까지 확인해 핵심 개념/구성요소, 인과·대립 축, 비자명한 인사이트를 먼저 추출한다. 기존 문서 글이 사실과 어긋나면 글부터 바로잡는다.
2. 임시 폴더(scratch 또는 OS 임시 폴더)에 생성 스크립트를 작성해 실행한다(일회성 생성 스크립트는 저장소에 커밋하지 않는다).
   ```python
   import sys
   sys.path.insert(0, '.agents/skills/docfig/scripts')
   from figlib import Flow, compare, matrix, network, figure, Doc

   d = Doc('docs/<문서>.html')
   d.insert_before('<h2 id="s2">', figure(svg, '도식이 보여 주는 핵심 통찰', 'fig-xxx'))
   # 대상 문서가 '버전 x.y'와 '변경 이력' 표·archive/ 보관을 쓰는 경우에만 선택 호출:
   # d.bump('그림 추가: …', date='YYYY-MM-DD')
   d.save()
   ```
3. 점검한다.
   ```bash
   python3 .agents/skills/docfig/scripts/figlib.py check docs/<문서>.html
   python3 .agents/skills/docfig/scripts/figlib.py shot  docs/<문서>.html <임시폴더>
   ```
   - `check`는 외부 의존성, `aria-label`, `figcaption`, 중복 ID뿐 아니라 **정적 SVG의 `viewBox` 밖 글자 잘림 우려**, **`network`의 단계 과다(7개 초과)·역방향 간선·없는 노드 참조**, 깨진 링크·앵커를 자동 검사한다.
   - Chrome/Edge가 있는 환경에서는 `shot`으로 밝은·어두운 화면 PNG를 찍어 눈으로 겹침을 확인한다.
4. 관련 문서 목록(`README.md` 등)이나 검증 절차가 있으면 함께 통과시키고, 요청된 커밋·푸시 규칙에 따라 반영한다.
5. 결과 보고: 어떤 도식으로 어떤 구조·인사이트를 시각화했는지와 `check`·`shot` 점검 결과를 간결히 전달한다.

## 6. 스크린샷과 Windows 계정 잠금 주의

- Windows에서 Chrome·Edge를 임시 프로필로 반복 실행하면 빈 암호 확인(`LogonUserW`, 이벤트 4625) 누적으로 OS 계정이 잠길 수 있다. 스크린샷은 고정 프로필을 재사용하는 `figlib.py shot`으로만 직렬 실행한다.
- 안전한 브라우저 실행 경로가 없는 환경에서는 억지로 우회하지 않고 `check` 결과와 함께 `shot` 미실행 사실을 정직하게 보고한다.

## 7. 자주 틀리는 곳

- **한 주제에서 잘 먹힌 화면 틀(특정 탭 이름, DB 열쇠 아이콘, 고정 팝업 등)을 다른 주제의 문서에 그대로 복제함** → 주제의 어휘와 문맥이 어색해진다. 틀이 아니라 **밀도 제어·의미 축·단방향·위상별 도식 선택 원리**만 적용한다.
- **수십 개 항목을 번호순으로 늘어놓고 선을 다 그음** → 의미 축 3~6개로 묶고, 2축 다대다는 `matrix`, 다단계 파급은 `network`, 1:1 전환은 `compare`로 나눈다.
- **글자가 상자나 `viewBox` 밖으로 넘침** → 상자 안 문구는 15~22자 이내 핵심 어구로 줄이고 `check`의 경계 경고를 확인해 폭·높이를 넉넉히 잡는다.
