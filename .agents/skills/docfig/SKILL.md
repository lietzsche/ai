# docfig — 문서 그림·연결도 넣기

HTML 문서에 **데이터가 어디로 흐르는지, 무엇이 무엇과 이어지는지, 어느 단계·주체가 어느 표·저장소를 쓰고 읽는지, 어느 열이 어느 원천 열에서 오는지**를 그림으로 넣는다. 모든 그림은 외부 라이브러리·웹폰트·이미지 없이 문서 안에 직접 들어가 오프라인·폐쇄망 환경에서도 그대로 열린다. 보조 도구는 [scripts/figlib.py](./scripts/figlib.py)(단독 복사본 프로젝트에서는 해당 스킬 폴더의 `scripts/figlib.py`). 사용자의 언어로 대화한다.

## 입력과 시작하기

- 요청에서 **대상 HTML 문서 경로**(지정하지 않으면 `docs/` 아래 관련 HTML 문서 탐색)와 **그림으로 보여 줄 대상**(단계 흐름, 시스템 구조, 2축 다대다 매핑, 다단 표·열 계보 등)을 확인한다.
- 코드·쿼리·설정·CSV·기존 문서에서 직접 확인할 수 있는 사실은 먼저 조사하고 사용자에게 다시 묻지 않는다.
- 문서 대상이나 그림 범위가 크게 갈릴 때만 한 번에 한 질문씩 확인한다. 선택형 질문은 에이전트의 선택형 질문 UI 지침을 따른다.

## 1. 그릴지 말지

- 그림은 **글로 조립해야 알 수 있는 구조**를 한눈에 보여 줄 때만 넣는다. 한 문장이면 끝나는 내용은 문장으로 둔다.
- **이름이 아니라 동작과 계기를 그린다.** 상자만 늘어놓지 말고, 데이터가 지나는 길·넘는 경계·언제 한 줄이 생기고 다시 계산되는지를 적는다.
- **화살표 방향과 뜻을 분명히 한다.** 정적 그림의 화살표에는 동작(`읽기`, `덮어씀`, `통과하면`)을 적고, 양쪽 끝을 다 동그라미로 두지 않고 삼각형 화살촉으로 상류 → 하류 방향을 분명히 한다.
- **있는 것과 없는 것을 모양으로 구분한다.** 아직 없는 단계·표·연결은 점선 테두리(`gap`, `plan`, `todo`)로 그린다. 계획을 지금 있는 것처럼 실선으로 그리지 않는다.
- 그림이 표를 대신하지 않는다. 본문 표·글은 검색·복사·스크린리더를 위해 남기고, 큰 방향 요약 그림을 앞에 두거나 대형 연결도는 탭(`tab_wrap`)으로 분리한다.

## 2. 어떤 그림을 쓸지

| 보여 줄 것 | 규모·성격 | 그림 | `figlib` |
| --- | --- | --- | --- |
| 순서대로 흐르는 처리·파이프라인·한 장 요약 | 상자 ~12개 안팎 | 흐름도 (정적 SVG) | `Flow` + `lane`·`card`(`box`)·`arrow` |
| 구성요소와 경계·있음/없음 연결 | 상자 ~15개 안팎 | 구조도 (정적 SVG) | `Flow` + `box(kind='group')` 묶음 |
| 두 축 사이의 다대다 관계 (단계 × 표, 주체 × 저장소, 환경 × 설정) | 1단계 대조 (열 ~12개 × 행 ~30개) | 매핑 격자 (정적 SVG) | `matrix` |
| 여러 층(3단 이상)을 거치는 표·모델·화면 연결과 열(컬럼) 단위 계보 | 표 10개 이상 또는 열 수십~수백 개 | 대화형 연결도·ERD | `lineage` (+ 긴 문서는 `tab_wrap`) |

- **2축 다대다 관계**를 선으로 이으면 엉키므로 `matrix` 격자로 그린다.
- **3단 이상 다단 파이프라인(`silver → gold → infer → 게시 표`)이나 열 단위 리니지**에서 수백 개 열을 처음부터 다 펼쳐 선으로 이으면 가로 수천 px 거미줄이 된다. 이럴 때는 반드시 `lineage`로 **기본은 '키만' 접기 + 선택 시 상·하류 끝까지 추적** 방식을 쓴다. 상세 스키마와 옵션은 [references/lineage.md](./references/lineage.md)를 읽는다.

## 3. 모양과 색의 뜻 (절제된 위계)

원색 배경 배지를 상자·열마다 다닥다닥 붙이지 않는다. 바탕은 차분한 패널 색(`--fg-panel`)으로 두고 **왼쪽 4px 색 막대**와 **테두리 실선/점선**으로 성격을 가른다.

| 구분 | 정적 `Flow` (`card` / `box`) | 격자 `matrix` 칸 | 다단 `lineage` (`tone` / `status`) |
| --- | --- | --- | --- |
| 원천·입력 층 | `card(..., tone='source')` / `box(kind='item')` | `r` (읽음) | `tone='source'`(`silver`) 회색 왼쪽 막대 |
| 결정론 계산·처리 단계 | `card(..., tone='calc')` / `box(kind='step')` | `w` (씀), `rw` (읽고 씀) | `tone='calc'`(`gold`) 파랑 왼쪽 막대, 하류 선 색 |
| LLM·모델 호출 / 사람 작업 | `card(..., tone='llm')` / `box(kind='llm'\|'person')` | `h` (사람이 함) | `tone='llm'`(`infer`) 주황 왼쪽 막대, `LLM` 칩 |
| 조립·게시·완료 | `card(..., tone='pub')` / `box(kind='ok')` | `ok` (완료·있음) | `tone='pub'` 초록 왼쪽 막대, 상류 선 색 |
| 아직 없음·계획·미구현 | `card(..., dashed=True)` / `box(kind='gap')` | `f` (점선), `c` (빈 자리) | `status='plan'\|'todo'\|'gap'` 점선 테두리, 열 미정 점(`cf='nd'`) |
| 개인정보·민감정보 | `box(kind='pii')` | 행의 `pii=True` | `tags=['개인정보']` 등 명시 |

- 범례(`legend`)는 같은 모양이 그림에 여러 번 나올 때만 넣는다(`lineage`는 실제 쓰인 층만 자동 생성).
- 색은 `figlib` 전용 변수(`--fg-*`, 밝은·어두운 화면 자동 대응)만 쓴다. `Doc`이 처음 저장할 때 필요한 CSS(및 `lineage` 사용 시 내장 스크립트)를 한 번만 넣는다.

## 4. 읽기 쉬운 그림의 5원칙

1. **의미 있는 레인과 부제 (4~7줄 이내)**: 시트 번호(`G01~G33`)나 임의 묶음으로 10줄 이상 늘어놓지 않는다. **역할·처리 층·줄이 생기는 계기(주기)**로 4~7줄 이내로 나누고, 각 레인 머리말에 "언제·무엇을 하는 줄인지" 부제를 적는다(`Flow.lane`, `lineage`의 `lanes`).
2. **단방향 위상 정렬 (역방향 간선 0개)**: 모든 흐름은 **왼쪽 → 오른쪽**(같은 레인 안에서는 위 → 아래)으로만 흐르게 배치한다. 서로 읽는 순환처럼 보이면 번호부(앞)와 요약 열(뒤 조립)처럼 단계로 갈라 역방향 화살표를 없앤다(`figlib.py check`가 역방향 간선을 잡는다).
3. **상류 높이에 맞춘 세로 배치**: 둘째 레인부터는 무조건 맨 위(`y=0`)부터 쌓지 않고, **자기가 읽는 왼쪽 상류 상자들의 평균 Y 좌표 근처**에 놓아 선이 짧고 수평에 가깝게 이어지게 한다(`lineage`는 자동 정렬).
4. **점진적 노출 (골격 먼저, 상세는 선택 시)**:
   - 본문 맨 앞에는 **4~5칸 이내의 한 장 요약 흐름도**로 큰 방향만 먼저 보여 준다.
   - 열이 많은 표 연결도(`lineage`)는 기본으로 **키 열 + 요약 1줄**(`그 밖 입력 5 · 계산 8`)만 노출하고, 평상시에는 **연한 표↔표 골격선**만 깔아 둔다. 표·열을 클릭했을 때만 **읽는 쪽(상류·초록)**과 **읽히는 쪽(하류·파랑)**을 끝까지(BFS 추이 폐포) 밝히며 **열↔열 계보선**과 양방향 상세 패널을 연다.
   - 본문이 긴 문서에 대형 연결도를 넣을 때는 `tab_wrap`으로 `설계 문서` / `연결도` 탭을 나누거나 `default_fit=True`로 폭에 맞춘다.
5. **정직한 확실도 표기**: 정적 `Flow`는 글자 11~13px·상자 안 한두 단어로 간결히 적고(`viewBox` 폭 1000 안팎, 화살표 간격 30~50px 이상), `lineage`에서는 확정된 연결(`ok`)·이름 기반 제안(`sg`)·열 미정(`nd`)·재료 없음(`no`)을 구분해 표시한다. 비밀정보·토큰·비공개 주소·실제 고객 개인정보는 절대 그리지 않는다.

## 5. 실행 순서

1. **사실을 먼저 확인한다.** 실제 코드·쿼리·설정·CSV·문서에서 확인한 것만 그린다. 문서 글이 실제 코드와 다르면 문서 글부터 고친다. 다단 표·열 연결도를 그릴 때는 먼저 [references/lineage.md](./references/lineage.md)를 읽고 레인 구분(층·계기)과 단방향 순서를 설계한다.
2. 그림 생성 스크립트를 임시 폴더(scratch 또는 OS 임시 폴더)에 작성해 실행한다. 일회성 생성 스크립트는 저장소에 커밋하지 않는다.
   ```python
   import sys
   sys.path.insert(0, '.agents/skills/docfig/scripts')  # 프로젝트 내 figlib.py 위치에 맞게 지정
   from figlib import Flow, matrix, lineage, tab_wrap, figure, Doc

   d = Doc('docs/<문서>.html')
   d.insert_before('<h2 id="s3">', figure(svg, '설명', 'fig-xxx'))   # 또는 insert_after, replace, replace_re
   # 문서가 '버전 x.y' 표기와 '변경 이력' 표·archive/ 보관을 사용하는 경우에만 호출:
   # d.bump('그림 추가: …', date='YYYY-MM-DD')
   d.save()
   ```
   - 판 올림(`d.bump`)은 대상 문서가 `버전 x.y`와 `변경 이력` 표를 관리하는 경우에만 프로젝트 규칙에 맞춰 한 작업당 한 번만 수행한다.
   - 기준 문자열(`anchor`)이 문서에 정확히 한 번 있어야 넣는다(아니면 멈추고 확인).
3. 점검한다.
   ```bash
   python3 .agents/skills/docfig/scripts/figlib.py check docs/<문서>.html
   python3 .agents/skills/docfig/scripts/figlib.py shot  docs/<문서>.html <임시폴더>
   ```
   - `check`가 외부 의존성, `aria-label`, `figcaption`, 중복 ID, 깨진 링크·앵커뿐 아니라 `lineage`의 **레인 과다(8개 초과), 역방향 간선(오른쪽→왼쪽), 없는 표·열 참조**까지 검사한다.
   - `shot`이 그림마다 밝은·어두운 PNG를 만든다. **PNG를 직접 열어** 글자 겹침·잘림·화살표 겹침이 없는지 확인하고, 있으면 고쳐 다시 넣는다.
4. 프로젝트의 `README.md`나 별도 문서 검증 스크립트가 있으면 함께 갱신·통과시키고, 커밋·푸시 규칙(`AGENTS.md` 또는 사용자 요청)에 따라 변경 파일만 스테이징해 커밋·푸시한다.
5. 결과 보고: 어느 문서 어느 절(또는 탭)에 무슨 그림을 넣었는지, 핵심 내용 한 줄, `check` 및 `shot` 확인 여부를 간결하게 답한다.

## 6. 스크린샷과 Windows 계정 잠금 (주의사항)

- **Windows에서 Chrome·Edge를 `--headless`로 직접 띄우지 않는다. 스크린샷은 반드시 `figlib.py shot`으로만 찍는다.**
- 이유: Windows용 Chrome은 새 임시 프로필로 시작할 때마다 빈 암호 확인용 로컬 로그인(`LogonUserW`, 보안 이벤트 4625)을 시도해 반복 실행 시 OS 계정이 잠길 수 있다. `figlib.py shot`은 고정 프로필(`%TEMP%\docfig-chrome-profile`)과 암호 변경 시각 캐시를 재사용한다.
- **`shot`을 여러 개 동시에 돌리지 않는다**(고정 프로필은 직렬로만 사용).
- Chrome/Edge가 없는 환경이어서 `shot`을 실행하지 못했다면 임시 프로필이나 비공식 우회를 쓰지 말고, `check` 결과와 함께 스크린샷 미실행 사실을 정직하게 보고한다.

## 7. 자주 틀리는 곳

- **시트 번호순으로 10줄 이상 레인을 쪼개고 수백 개 열을 기본으로 다 펼침** → 가로 6,000px 거미줄이 된다. 층·계기 기준 4~7개 레인으로 묶고 `lineage`의 `키만` 기본 모드를 쓴다.
- **오른쪽에서 왼쪽으로 거슬러 가는 역방향 화살표 또는 양끝 동그라미** → 읽는 방향을 잃는다. 상류 → 하류 단방향으로 레인을 배치하고 삼각형 화살촉을 쓴다.
- **평상시부터 모든 열↔열 선과 원색 배지를 다 그림** → 평상시엔 연한 표 단위 골격선과 왼쪽 4px 색 막대만 두고, 클릭 시에만 상류(초록)·하류(파랑) 열 계보선을 켠다.
- **정적 `Flow`에서 글자가 상자·화살표와 겹치거나 오른쪽 끝이 잘림** → 상자 간격을 50px 이상 두고(`Flow.arrow` 기본 배경 패드 활용), 끝 글자는 `anchor='end'`로 맞추거나 `viewBox` 폭·시작점(`x0`, `y0`)을 조정한다.
- **한 문서에 그림이 둘 이상인데 `mid`나 `fid`가 같음** → marker/그림 ID 충돌이 나므로 그림마다 고유하게 짓는다(`check`가 잡음).
- **미구현·계획을 실선으로 그리거나 본문 표를 지움** → 계획·단절은 점선(`gap`, `plan`, `todo`)으로 구분하고 본문 표는 그대로 남긴다.
