# 스킬 메이커 (Skill Maker)

아이디어나 특정 도구의 내장 워크플로(예: Antigravity의 `/boost`, `/teamwork` 등)를 Codex와 Claude Code 양쪽에서 재사용할 수 있는 스킬로 설계·작성한다. 사용자의 언어로 대화한다.

## 입력과 범위 확인

- 요청에서 **스킬 이름**(소문자·하이픈, 예: `boost`, `teamwork`), **목적과 호출 상황**, **참고할 원본 기능이나 워크플로**를 파악한다.
- 저장소 파일(`AGENTS.md`, `README.md`, 기존 `skills/*/SKILL.md`, `docs/*.html`)이나 공식 문서에서 확인할 수 있는 사실은 먼저 직접 조사하고 사용자에게 다시 묻지 않는다.
- 설계 방향이 크게 갈리는 핵심 불확실성이 있을 때만 한 번에 한 질문씩 확인한다. 선택형 질문은 `skills/grill-me/SKILL.md`의 선택형 질문 UI 지침을 따른다.
- 사소한 공백은 합리적으로 정해 작성한 뒤 결과 보고에 가정으로 남긴다. 요구사항이 전반적으로 모호하면 `skills/grill-me/SKILL.md`로 인터뷰를 먼저 진행할지 안내한다.

## 파일 구조와 진입점

스킬을 추가하거나 변경할 때는 기본적으로 다음 세 파일을 함께 구성한다.

1. **공통 원본 (`skills/<name>/SKILL.md`)**
   - 실제 워크플로, 실행 단계, 단계 간 전달할 입력·산출물, 환경별 도구 분기, 종료 조건을 모두 이 파일에 작성한다.
   - 꼭 필요한 경우에만 `skills/<name>/` 아래에 `assets/`, `references/`, `scripts/`를 추가한다.
2. **Codex 진입점 (`.agents/skills/<name>/SKILL.md`)**
   - 유효한 `name`, `description` YAML frontmatter(들여쓰기 2칸)를 둔다.
   - 본문에는 지침을 복제하지 않고, 저장소 루트 기준 `skills/<name>/SKILL.md`를 읽고 따르도록 안내하는 얇은 진입점만 작성한다.
3. **Claude Code 진입점 (`.claude/skills/<name>/SKILL.md`)**
   - Codex 진입점과 동일하게 frontmatter와 `skills/<name>/SKILL.md` 참조만 둔다.

## 타 도구 기능 이식과 환경별 분기

다른 도구(예: Antigravity CLI의 `/boost`, `/teamwork`)의 내장 명령을 Codex와 Claude Code용 스킬로 옮길 때는 다음 원칙을 따른다.

- **핵심 메커니즘 분해**: 원본 도구의 비공개 시스템 프롬프트나 전용 슬래시 명령이 다른 클라이언트에 그대로 있다고 가정하지 않는다. 원본 기능이 문제를 푸는 구조(예: `Orchestrator 설계 → 다중 가설·역할 분할 → 심층 구현·탐색 → 독립 검증`)를 명시적인 단계와 체크리스트로 풀어 쓴다.
- **서브에이전트·병렬 작업 매핑**: 멀티에이전트 협업이나 격리 실행이 필요한 스킬은 호스트 환경별 실행 방법과 대체 동작(Fallback)을 함께 적는다.
  - **Claude Code**: 서브에이전트 위임 도구(예: `Task` / `Agent` 도구)를 사용할 수 있으면 역할별 목적과 완료 기준을 담아 위임하고, 서로 독립적인 조사·검증 단계는 병렬로 호출한다.
  - **Codex**: 현재 세션에서 서브에이전트·멀티에이전트 도구가 제공되면 이를 우선 사용한다. 도구가 없거나 제한된 환경에서는 격리된 작업 트리(`git worktree`)나 하위 실행이 허용된 경우 이를 활용하고, 그렇지 않으면 메인 에이전트가 단계별 역할(설계자 → 구현자 → 검증자)을 순차 전환하며 수행한다.
  - **단일 에이전트 대체 동작**: 서브에이전트 생성이 불가능한 모드나 환경에서도 스킬이 멈추지 않도록, 한 에이전트가 단계별 산출물과 독립 검증 절차를 순서대로 수행하는 대체 경로를 반드시 명시한다.
- **선택형 질문 UI 연결**: 사용자에게 선택지를 물어봐야 하는 단계가 있으면 지침을 중복 작성하지 않고 `skills/grill-me/SKILL.md`의 선택형 질문 UI 지침을 따르도록 연결한다.
- **스킬 체인 연결**: 다른 스킬로 이어지는 워크플로는 `/명령`을 실행한다고 쓰지 말고, 대상 스킬의 `skills/<target>/SKILL.md`를 읽고 어떤 입력을 넘기며 언제 종료하는지 명시한다.
- **권한과 제한 명시**: 기존 승인·샌드박스 경계를 임의로 우회하지 않는다. 원본 기능과 비교해 클라이언트 환경상 지원 제한(예: 수일간 도는 클라우드 데몬 부재 등)이 있으면 참고 섹션에 명확히 설명한다.

## 공통 원본(`SKILL.md`) 작성 원칙

- **YAML Frontmatter**:
  - `name`: 스킬 폴더 이름과 일치하는 소문자·하이픈 문자열
  - `description`: 스킬이 하는 일과 언제 호출해야 하는지(`사용자가 <name> 또는 ...을 요청할 때 사용한다`)를 한두 문장으로 요약
- **본문 구성**:
  - **시작하기 / 입력**: 호출 인자, 기존 대화 맥락, 사전 조사할 저장소 사실 정의
  - **실행 단계**: 각 단계의 역할, 입력과 산출물, 다음 단계로 넘어가는 조건을 순서대로 기술
  - **검증과 마무리**: 결과를 검증하는 방법, 사용자에게 제시할 최종 요약·산출물 형식, 종료 조건
  - **참고(선택)**: 모티프가 된 원본 기능의 공식 문서 출처와 독립 스킬임을 밝히는 안내문

## 문서 반영과 검증

1. **문서 업데이트**:
   - `README.md`의 스킬 표에 새 스킬을 추가하고, 본문에 Codex(`$<name>` 및 `/skills`)와 Claude Code(`/<name>`) 사용 예시를 함께 작성한다.
   - 일반 대화 요청도 스킬로 라우팅할 필요가 있으면 `AGENTS.md`의 `Agent-Specific Instructions`에 추가한다(`CLAUDE.md`의 `@AGENTS.md` 참조가 유지되는지 확인한다).
2. **완료 전 검증**:
   - `skills/<name>/SKILL.md`, `.agents/skills/<name>/SKILL.md`, `.claude/skills/<name>/SKILL.md`의 frontmatter(`name`, `description`), 원본 경로, 참조 파일 경로를 확인한다.
   - 현실적인 요청 예시를 대입해 단계 순서, 미정 사항 처리, 환경별 대체 동작, 최종 산출물이 모순 없이 이어지는지 점검한다.
   - `git diff --check`로 공백 및 줄바꿈 오류를 확인한다.
3. **정직한 보고와 커밋**:
   - 실제 Codex나 Claude Code 클라이언트에서 스킬 목록 표시·자동완성·런타임 호출을 직접 실행해 확인하지 못했다면 그 사실을 명시하고, 파일 생성만으로 클라이언트 발견까지 검증했다고 보고하지 않는다.
   - 검증이 끝나면 `AGENTS.md`의 커밋·푸시 규칙에 따라 작업 파일만 스테이징하여 한글 커밋 메시지로 커밋하고 원격 저장소에 푸시한다.
