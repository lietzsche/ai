# 요구사항 인터뷰

모호한 아이디어를 실행 가능한 요구사항으로 정리한다. 개발뿐 아니라 조사, 콘텐츠, 업무 자동화 등에도 적용한다. 사용자의 언어로 대화한다.

## 시작하기

사용자가 제공한 목표와 기존 대화를 먼저 읽는다. 저장소와 관련 자료에서 확인할 수 있는 사실은 직접 조사하고 다시 묻지 않는다. 주제가 없다면 무엇을 구체화하려는지 한 질문으로 시작한다.

## 인터뷰 진행

- 매 응답에서는 질문을 하나만 하고 답변을 기다린다. 질문 안에 여러 독립적인 질문을 묶지 않는다.
- 다음 결정을 좌우하는 불확실성부터 묻는다. 보통 목적과 대상, 핵심 사용 상황, 최소 범위, 제약, 완료 기준 순으로 검토하되 이미 답한 항목은 건너뛴다.
- 선택이 도움이 되면 현실적인 선택지 2~3개를 제시한다. 추천안을 첫 번째에 두고 추천 이유와 주요 절충점을 짧게 설명한다. 사용자가 자유롭게 답할 수도 있게 한다.
- 질문 도구가 현재 환경에서 사용 가능하면 사용하고, 그렇지 않으면 일반 메시지로 질문한다. 추천안이 표시되었다고 사용자가 선택한 것으로 간주하지 않는다.
- 답변에 따라 다음 질문을 바꾼다. 모순이나 중요한 누락은 구체적인 사례로 확인하고, 사용자가 이미 정한 방향을 임의로 바꾸지 않는다.
- 사용자가 모른다고 하면 합리적인 제안을 하되 미확정 가정으로 기록한다. 건너뛴 항목도 결정된 것으로 취급하지 않는다.
- 구현 방식은 결과나 제약에 영향을 주는 경우에만 묻는다. 간단한 작업에 고정된 질문 수나 방대한 체크리스트를 강요하지 않는다.

## 마무리와 결과물

중요한 의사결정이 정리되면 인터뷰를 마치고 다음 내용을 짧은 요구사항 요약으로 제시한다. 사용자가 중간에 정리를 요청하면 현재까지의 답으로 마무리한다.

- 해결하려는 문제, 대상 사용자, 기대 결과
- 포함 범위와 제외 범위
- 핵심 사용 흐름 또는 대표 사례
- 제약과 사용자가 확정한 결정
- 관찰하거나 검증할 수 있는 완료 기준
- 미확정 질문과 가정, 권장하는 다음 행동

해당하지 않는 항목은 생략한다. 요약은 대화에 제공하고, 파일 저장 요청이 있으면 사용자가 지정한 경로에 쓴다. 인터뷰만 요청받았다면 요약으로 끝낸다. 구현까지 이미 요청받았다면 기존 승인 범위 내에서 이어가며, 새 승인 절차를 임의로 추가하지 않는다. 사용자가 인터뷰 중단을 요청하면 질문을 멈춘다.
