Explanation · 탐색 스킬 작동 원리

find-skills는 어떻게 작동하는가

“X를 하는 스킬이 있을까?” 같은 요청을 받으면 에이전트가 후보를 검색하고 품질 기준을 대조한 뒤 설치 명령을 제안하도록 안내하는 지침입니다.

역할 분담 MIT

실제 패키지 검색과 파일 배치는 skills CLI(npx skills)가 수행하고, find-skills는 에이전트가 언제 어떤 검색어와 검증 기준으로 이 CLI를 호출할지 규정합니다.

출처: find-skills SKILL.md ↗

작동 조건

  • “X는 어떻게 해?”에서 X가 반복 가능한 전문 작업일 때
  • “X용 스킬 찾아줘”, “X 하는 스킬 있어?”라고 물을 때
  • 문서화·테스트·배포·리뷰 등 특정 분야 워크플로를 확장할 때

6단계 탐색·검증 절차

  • 1단계: 분야와 구체적 작업 목표 정의
  • 2단계: skills.sh 상위 검증 목록 먼저 확인
  • 3단계: npx skills find <검색어>로 후보 탐색
  • 4단계: 설치 수(1K+)·출처 신뢰도·GitHub 스타(100+)·라이선스 검증
  • 5단계: 스킬 이름·용도·지표·설치 명령·링크 제시
  • 6단계: 사용자 승인 또는 저장소 규칙에 따라 설치

적합한 스킬이 없을 때

품질 기준을 통과하는 스킬이 없으면 억지로 설치하지 않고 에이전트의 기본 기능으로 직접 해결합니다. 같은 작업을 반복해야 한다면 npx skills init <이름>으로 자체 스킬을 만들도록 안내합니다.

How-to · 설치와 경로 설계

설치 방법

실행 전 node -v로 Node.js 22.20 이상인지 먼저 확인하세요. 저장소 루트에서 실행하면 프로젝트 범위로 설치됩니다.

이 저장소에 설치 권장 표준

npx skills add <owner/repo> \
  --skill <name> -a claude-code -a codex

Claude Code와 Codex 양쪽에 프로젝트 범위로 설치합니다. 비대화형 환경에서 확인 프롬프트를 생략하려면 -y를 덧붙입니다.

출처: skills add 공식 문서 ↗

대화형으로 선택 설치

npx skills add vercel-labs/skills

저장소 안의 여러 스킬과 대상 에이전트를 화면에서 직접 고릅니다. 연결 방식은 단일 원본 유지에 유리한 심볼릭 링크(권장)와 복사 중 선택합니다.

개인 전역 환경에 설치 전역 -g

npx skills add vercel-labs/skills \
  --skill find-skills -g -a claude-code -a codex

이 저장소에 커밋하지 않고 내 PC의 모든 프로젝트에서 쓰려면 -g를 붙여 사용자 홈 폴더에 설치합니다.

설치 상태·무결성 점검

npx skills list
npx skills check

list는 설치된 스킬과 skills-lock.json 대조 상태를 출력하고, check는 원격 업데이트와 로컬 임의 변경 여부를 검사합니다.

Reference · skills CLI 명령 사전

skills CLI 전체 명령 (10개)

모든 명령은 npx skills <명령> 형식으로 실행합니다. experimental_ 접두어가 붙은 명령은 예고 없이 사양이 바뀔 수 있습니다.

행을 클릭하거나 Tab 이동 후 Enter를 누르면 상세 옵션·예제 복사·공식 문서 링크가 펼쳐집니다. 검색·분류·펼침 상태는 URL에 보존됩니다.

명령분류별칭설명

skills use <source>@<skill>설치설치 없이 단일 스킬 프롬프트 출력 또는 에이전트 실행

Guardrails · 운영 주의 사항

주의 사항

버전 요구사항, 개인정보·보안 감사 설정, 이름 충돌, 해시 불일치를 예방하는 4가지 필수 수칙입니다.

Node.js 22.20 이상 필수

실행 전 node -v를 먼저 확인하세요. 낮은 버전이 기본 경로에 잡혀 있으면 nvm use 22 등으로 Node.js 22.20 이상을 활성화한 뒤 npx skills를 실행합니다.

익명 텔레메트리와 보안 감사

CLI는 기본적으로 익명 사용 통계를 전송합니다. 전송을 차단하려면 실행 앞에 DISABLE_TELEMETRY=1 또는 DO_NOT_TRACK=1 환경 변수를 지정하세요(단, 설치 시 원격 보안 감사 표시는 함께 생략됩니다).

출처: Telemetry 안내 ↗

동명 스킬 덮어쓰기 방지

서로 다른 저장소에서 같은 이름의 스킬을 그대로 설치하면 기존 폴더를 덮어씁니다. 이름이 겹칠 때는 설치 명령에 --rename <새이름>을 붙여 분리하세요.

설치 원본 직접 수정 금지

외부에서 설치한 .agents/skills/<이름>/ 파일을 직접 고치면 skills-lock.json 해시와 어긋나 list에서 modified로 경고되고 check가 실패합니다(Windows 줄바꿈 자동 변환도 해시 차이를 유발할 수 있음). 변경은 npx skills update나 재설치로만 처리합니다.

C · 세션 인계(handoff) 두 구현 방식 비교

조사 대상 구분 안내

진행 상태를 파일로 남기고 새 세션이나 컨텍스트 압축 이후에 이어받는 세션 인계 기능입니다(Ultrapack의 자율 실행 규약 handsoff나 Android 앱 HandsOff와는 무관). 아래 두 후보 중 검증 지표와 라이선스가 확인된 Matt Pocock의 handoff를 이 저장소에 정식 설치했으며, 훅 기반 후보는 참고 기록으로만 남겼습니다.

1) Matt Pocock의 handoff — 요약 인계서 생성 후 수동 전달 (설치됨)

현재 대화를 요약 문서로 작성해 다음 세션 에이전트가 읽게 하는 방식입니다. 작업 저장소를 더럽히지 않도록 OS 임시 폴더에 저장하고, 기존 명세·커밋·diff는 경로로만 참조하며 API 키·암호 등 민감 정보는 제거합니다. SKILL.md 원문 ↗

현재 세션: /handoff 다음 세션에서는 로그인 오류 수정에 집중
→ 출력된 OS 임시 폴더 인계 문서 경로 확인
→ 새 세션 시작 후 “이 인계 문서를 읽고 미완료 작업부터 이어가 줘” 요청

2) xoonjaeho/claude-skill-handoff — 상태 저장 후 SessionStart 훅 재주입 (미설치 참고)

README 기준 /clear 또는 /compact 실행 전 상태(~/.claude/handoffs/handoff.md)를 저장하고 SessionStart 훅으로 조건부 자동 재주입하는 구조입니다. 조사 당시 MIT 라이선스이나 0스타 상태로 확인되어 설치 대상에서는 제외했습니다. 저장소·README ↗
