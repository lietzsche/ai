find-skills란

“X를 하는 스킬이 있을까?” 같은 질문을 받으면 에이전트가 스킬을 찾고, 품질을 확인한 뒤 설치 명령을 제안하게 만드는 스킬입니다.

무엇을 하나 MIT

오픈 에이전트 스킬 생태계에서 스킬을 찾아 설치하도록 돕습니다. 실제 검색과 설치는 skills CLI(npx skills)가 하고, find-skills는 에이전트가 이 CLI를 언제 어떻게 쓸지 알려 주는 지침입니다.

출처: find-skills SKILL.md ↗

언제 작동하나

  • “X는 어떻게 해?”에서 X가 흔한 작업일 때
  • “X용 스킬 찾아줘”, “X 하는 스킬 있어?”
  • 디자인·테스트·배포 같은 분야의 도움을 원할 때
  • 에이전트 기능을 넓히고 싶다고 할 때

에이전트가 따르는 6단계

  • ① 분야와 작업 파악 → ② skills.sh 순위표 확인
  • ③ npx skills find <검색어>로 검색
  • ④ 설치 수·출처·스타로 품질 확인
  • ⑤ 이름·용도·설치 수·설치 명령·링크 제시
  • ⑥ 사용자가 원하면 설치

못 찾으면

맞는 스킬이 없으면 그렇다고 알리고 일반 능력으로 직접 돕겠다고 제안합니다. 자주 하는 일이라면 npx skills init으로 직접 스킬을 만들도록 권합니다.

설치

Node.js 22.20 이상이 필요합니다(node -v로 확인). 프로젝트 폴더에서 실행하면 기본으로 그 프로젝트에 설치됩니다.

이 저장소에 설치 권장

npx skills add vercel-labs/skills \
  --skill find-skills -a claude-code -a codex

Claude Code와 Codex 양쪽에 프로젝트 범위로 설치합니다. 확인 질문을 건너뛰려면 -y를 붙입니다.

출처: skills add ↗

대화형으로 설치

npx skills add vercel-labs/skills

설치할 스킬과 에이전트를 화면에서 고릅니다. 설치 방식은 심볼릭 링크(권장)와 복사 중에서 고릅니다.

모든 프로젝트에서 쓰기 전역

npx skills add vercel-labs/skills \
  --skill find-skills -g -a claude-code -a codex

-g는 사용자 폴더(~/.claude/skills/, ~/.agents/skills/)에 설치합니다.

설치 확인

npx skills list
npx skills check

list는 설치된 스킬과 skills-lock.json 기준 상태를, check는 업데이트와 로컬 변경 여부를 보여줍니다.

skills CLI 명령

모든 명령은 앞에 npx를 붙여 npx skills <명령>으로 실행합니다. experimental_ 명령은 미리보기라 언제든 바뀔 수 있습니다.

명령을 클릭하거나 Tab으로 이동해 Enter를 누르면 자세한 설명과 사용 예, 공식 문서 링크가 펼쳐집니다. 검색어와 펼친 항목은 주소에 남아 그대로 공유할 수 있습니다.

주의 사항

Node.js 버전

CLI는 Node.js 22.20 이상이 필요합니다. 낮은 버전이면 먼저 Node.js를 올립니다.

텔레메트리

CLI는 익명 사용 데이터를 수집합니다. 끄려면 DISABLE_TELEMETRY=1이나 DO_NOT_TRACK=1을 설정합니다. 이 설정은 보안 감사 요청도 함께 끕니다.

출처: Telemetry ↗

이름이 겹칠 때

같은 이름의 스킬을 다른 출처에서 설치하면 먼저 설치한 것을 덮어씁니다. --rename <name>으로 다른 이름을 붙여 설치합니다.

설치한 스킬은 직접 고치지 않기

직접 수정하면 skills-lock.json의 해시와 달라져 list에서 modified로 표시되고 check가 실패합니다. 바꿔야 하면 업데이트나 재설치로 처리합니다.

04 · handoff — 세션을 이어가는 인계 스킬

사용자가 찾는 기능에 맞춰 조사 대상을 정정했습니다.

진행 상태를 파일로 남기고 새 세션이나 압축 이후의 컨텍스트에서 읽어 작업을 이어가는 handoff입니다. Ultrapack의 자율 실행 규약 handsoff 및 Android 도구 HandsOff와는 다릅니다. 아래 두 후보가 설명에 부합하지만 사용자가 들었던 링크가 없어 특정 제작자는 미확정입니다. Matt handoff는 이후 이 프로젝트의 Codex·Claude Code 양쪽에 설치했습니다. 훅 기반 후보는 설치하지 않았고, 실제 클라이언트 호출은 아직 확인하지 않았습니다.

A. Matt Pocock의 handoff — 요약 문서를 만들어 전달

현재 대화를 인계 문서로 요약해 새 에이전트가 작업을 이어가도록 준비하는 커뮤니티 스킬입니다. grill-me와 같은 제작자의 저장소에 있어 이전 대화 맥락에서는 유력한 후보지만, 사용자가 들은 스킬이라고 확정할 수는 없습니다. SKILL.md 원문

원문에서 확인한 동작
  • 작업 저장소가 아닌 OS 임시 폴더에 인계 문서를 저장합니다.
  • 이미 명세·계획·ADR·이슈·커밋·diff에 있는 내용은 중복하지 않고 경로나 URL로 참조합니다.
  • suggested skills 항목으로 다음 에이전트가 사용할 스킬을 남깁니다.
  • API 키·암호·개인정보 등 민감한 내용을 제거합니다.
  • 다음 세션의 목적을 인자로 받으면 그 목적에 맞춰 작성합니다.
  • 사용자가 직접 호출하는 설정입니다. 이 파일 자체에 자동 재주입 훅은 없습니다.
현재 세션: /handoff 다음 세션에서는 로그인 오류 수정에 집중
→ 인계 문서 경로 확인
→ 새 세션 시작
→ “이 인계 문서를 읽고 미완료 작업부터 이어가 줘”

설치 후의 사용 예시이며 실제 호출명은 플러그인 이름 공간에 따라 달라질 수 있습니다. 이번 환경에서 실행하지 않았습니다. 저장소 라이선스는 MIT입니다. 저장소·라이선스

B. xoonjaeho/claude-skill-handoff — 저장 후 훅으로 다시 읽기

README는 /clear 또는 /compact 전에 정확한 ID·진행 위치·결정과 이유 등을 파일에 보존하고 SessionStart 훅으로 다시 주입한다고 설명합니다. “압축 뒤 자동으로 다시 읽는다”는 기억과 더 가까운 후보입니다. MIT 라이선스이며 조사 당시 0스타로 표시되어 널리 검증된 도구라고 단정할 근거는 부족합니다. 저장소·README

  • /handoff는 ~/.claude/handoffs/handoff.md에 선택한 상태를 저장합니다. 대화 전체 백업은 아닙니다.
  • 사용자가 /clear 또는 /compact를 실행합니다. 스킬이 해당 명령을 대신 실행하지 않습니다.
  • 훅은 clear·compact 출처에서 인계서를 보관 처리하고, 10분 이내 자료는 자동 주입하며 오래된 자료는 확인을 요청합니다.
  • 일반 새 세션 시작에는 자동 주입하지 않습니다. 수동 재개 명령이나 파일 읽기가 필요합니다.
  • 자동 재개에는 훅 등록과 Python 3.9 이상이 필요합니다. 단일 대기 파일을 사용하므로 여러 세션의 동시 인계에는 제약이 있습니다.

compact와 함께 사용할 때의 의미

인계서는 목표·결정·제약·진행 상태·참조 파일·다음 행동을 명시적으로 남기는 산출물입니다. 원본 대화나 파일 시스템 전체를 복제하지 않습니다. 이어받는 세션은 문서를 읽은 뒤 실제 파일·브랜치·실행 결과를 확인해야 합니다. 위 구현들을 바탕으로 한 활용 원칙이며, 인계서가 완전한 복원을 보장한다는 뜻은 아닙니다.
